# skill

GameCoach 的游戏业务层：保留用户原话，整理相关背景，交给通用 `ai-core`，原样传回正文。它帮助模型理解当下的问题，而不是每轮强制执行“阵容报告”。不增加一次分类 AI 调用，不需要 Backend。

## 代码结构

```text
skill/
├── index.js             # 冻结本次输入 → 准备资料 → ai-core → 输出
├── rules.js             # 职责、非常规选择、事实边界、自然对话规则
├── input/
│   ├── game.js          # 当前/历史游戏、选人、有效 Ban、BP 规则
│   ├── knowledge.js     # 按问题取技能节选、决定是否允许检索
│   └── prepare.js       # 阵容去重、明确条件、应用状态、引用目标、消息组装
├── output/
│   └── index.js         # 每次请求的原文流式透传与最终处理入口
└── README.md
```

建议依次读 `index.js`、`rules.js`、`input/prepare.js`，然后看各资料模块。相关前端逻辑在 `frontend/conversation.js`：筛选有效历史、摘录用户声明、定位被点击的回答；重试与 Google 接口适配在 `ai-core/`，来源显示在 `frontend/message-sources.js`。

普通脚本顺序加载，兼容双击 HTML 和 GitHub Pages；Skill 不直接读 DOM、存储、用户路径或 API Key。

## 输入接口

```js
const response = await GameCoachSkill.run(messages, {
  context: {
    draft, memory, // 独立长期记忆；不直接传玩家资料
    declarations,  // 最多三个用户自己的明确条件原话，后续更正优先
    lastCall,      // 上次失败/停止事件，不把错误文字伪装成模型历史
    expansion,     // 可选：被点击回答的 ID、正文、原问题和当时阵容
    searchMode: 'auto', // auto / on / off
  },
  mode: 'quick', signal,
  onRetry({ attempt, maxAttempts }) {},
  onDelta(text) {},
});
```

messages 可以是非空字符串或末尾为 user 的消息列表；支持 system/developer/user/assistant。正文及已有多模态内容片段保留，不重写用户问题。历史 user 消息可带 `draft`，assistant 可带本地 `id`；发送给核心前去掉这些元数据，只保留 role/content。

`GameCoachSkill.prepare(messages, context)` 可独立检查组装结果，不调用模型、不联网、不保存。context 是明确字段白名单，任意字段不会直接拼入提示词。偏好、资料和检索结果放在 user 级背景里，不能提升为系统指令。

## 本次修正的行为

- 用户本轮问题优先。阵容只是可选背景；闲聊、反馈、纠错和连接状态询问不应自动触发整份阵容分析。
- Quick/Coach 是回答执行档位，不是快速匹配或大乱斗。Quick 自然简短，Coach 默认只展开当前问题；两档仍真实切换模型及思考配置，不强制打印“结论/理由”。
- 用户明确的英雄、位置、搭档与打法是分析条件。非常规选择也分析目标、机制、经济、成立条件和风险；不擅自换位、换英雄，不把辅助固定理解为保人，也不为迎合用户编造可行性。
- 最新更正优先，旧 AI 回答不是事实来源。用户常用位置不等于本局位置，用户明确声明优先于编辑器的初始位置。
- 游戏版本的不确定性只限制有差异、未核实的部分；可靠的共通机制仍可用于分析并说明来源。不能仅凭旧记忆否认目录里已有的英雄，不能编造未知技能、数值和装备效果。

这些是模型遵循的行为约束，不能保证每次生成都正确，因此另有真实模型验收案例。

## 背景整理与压缩

`game.js` 用对应游戏目录转换名称。普通阵容保留固定分路，BP 选人编号不推断分路，空位仍未知。只发送当前有效 Ban；关闭 BP 后隐藏的 Ban 和三禁规则的第四、第五禁位不发送。BP 同时附规则及下一禁选位。明确传入未接入游戏会报错，旧数据缺 gameId 按手游迁移。

相同阵容在一次请求中只展开一次，不同快照用“当前/历史1”等短引用关联；旧消息没有快照时不套用当前阵容。资料定义放在最新问题附近，历史原话保留。玩家资料不再直接注入 Skill；统一作为独立记忆管理，`context.profile` 不会被读取。

长期经验经 `memory/retrieve.js` 按问题选择，作为 user 级可选参考附入。常用位置、英雄池仅在明确询问个人经验时参与，不限制本局分工和候选。没有给记忆设置神秘的数值权重；当前任务和事实优先，不要求每轮按经验清单输出。结构、预算与使用方法见 [memory/readme.md](../memory/readme.md)。

前端最多取最近 20 条有效历史，排除失败、停止和演示回复。额外保留最多三个用户明确条件的短原话，不把模型猜测总结成用户事实。上次失败只补一个应用状态事件，让“现在呢”能够结合失败理解，不假装已经恢复连接。

技能资料按具名英雄或阵容问题选取。具名提问优先完整描述，整套阵容取短节选；技能正文预算 4800 字符，每项最多 600/80 字符，截断标“节选”。这是字符预算，不是准确 Token 数；不发送头像、整个英雄表或整个资料库。接口返回实际 usage 时保留，不声称已实现 Token 最优压缩、历史摘要或精确 Token 截断。

“前三级呢 / 为什么”等相关短追问，可从最近两条用户原话找回提过的英雄；不从旧 AI 回答推断新的英雄事实，闲聊或“现在呢”本身不拉入旧技能资料。

## 版本与检索

本地资料位于 `resources/lol/knowledge.js` 和 `resources/lolm/knowledge.js`，保留游戏、来源、版本和采集日期。当前是端游 16.20.1 / 手游目录 7.3 的官方快照；两者分开，不能保证等于本场比赛版本。维护方式见 [resources/README.md](../resources/README.md)。尚无完整装备/属性计算数据。

auto 仅在版本、更新、重做、上线或明确查资料的请求中允许 Google Search；on 每次允许；off 不提供工具。“现在呢”本身不触发搜索。这只是是否提供工具，实际使用由模型决定，不能声称每次都搜索。允许搜索会增加潜在延迟和用量；UI 的 AI 连接面板可修改。

本地引用与实际联网来源分别标注；只在接口返回搜索证据时标为联网。Google 返回的搜索建议经过清理后在隔离 iframe 显示。没有实际检索不得声称已查过；资料快照不冒充实时版本。

## 深入解释

按钮携带被点击回答、原问题和当时阵容。若目标仍在最近历史中只加定位标记；超出窗口或旧消息没有 ID 则附原回答。只展开相关观点，发现原答错误先纠正，不重新套整份阵容报告。当前 BP 编辑器不会因展开旧答案被覆盖；新消息记录 inReplyTo 以便继续引用。

## 失败处理

`ai-core` 对未输出正文的临时网络、限流、服务错误最多尝试三次，共用模式总超时，尊重 Retry-After。取消、密钥/权限/参数错误不重试；已经输出部分文字不自动拼接另一份答案。页面显示重试进度、实际失败次数，并提供手动重试。没有第二个平台回退，也不更改付费配置。

## 输出扩展位置

`output/index.js` 每个请求创建 stream/finish 处理器，当前正文原样透传，保留模式、模型、时延、结束状态、尝试次数和用量。入口补充实际使用的本地/联网来源，UI 负责显示。未来可在输出端加入统一规则评分、可选轻量 AI 整理、实体资料卡；当前未实现，不生成占位分数。

## 验证

```powershell
node --test tests/*.test.cjs
```

覆盖阵容快照、白名单、版本来源、资料预算、按钮引用、失败事件、检索请求与元信息、流式一致性、取消、重试和本地保存。接口测试使用模拟响应，不读取用户密钥、不消耗账号额度。

浏览器打开 `tests/sources.html` 可验证来源显示与搜索建议 HTML 隔离、过滤，不调用 API。

[skill-quality-cases.json](../tests/skill-quality-cases.json) 记录非常规辅助、英雄旧记忆、闲聊、档位、失败后追问、按钮目标、短追问、事实更正、版本核实及诚实边界的真实模型验收条件。需要用户自己的 Key 实际验证；结构测试通过不能替代语义验收。长期规划见 [readme-vision.md](../readme-vision.md)。
